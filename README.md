# دفتر الفواتير — مستودع مُدمج (سطح المكتب + أندرويد)

هذا المستودع يجمع نسختين من نفس البرنامج بمجلد واحد:

```
.
├── desktop/   ← نسخة سطح المكتب (Electron) — دفتر الفواتير الأصلي
├── android/   ← نسخة أندرويد (Kotlin) — قيد البناء التدريجي
└── .github/workflows/build-all.yml  ← يبني الاثنين معاً بكل رفعة (push)
```

## البناء التلقائي — الفكرة
كل مرة ترفع تعديل (`git push`) على فرع `main`، GitHub يشغّل **الملفين مع بعض بالتوازي**:
1. **desktop** → يبني نسخة تثبيت ويندوز (`.exe`) عبر electron-builder.
2. **android** → يبني ملف APK عبر Gradle.

بعد ما يخلص الاثنين، ينشئ **Release واحد** على GitHub بنفس الرقم (`v1.0.<رقم التشغيل>`) **وفيه الملفين معاً** — ملف `.exe` وملف `.apk` — جاهزين للتحميل من تبويب **Releases**.

## رفعه على GitHub لأول مرة
1. أنشئ مستودع جديد وخاص على GitHub (بدون README تلقائي).
2. من المجلد الجذر لهذا المشروع (الذي يحتوي `desktop/` و`android/` معاً):
   ```bash
   git init
   git add .
   git commit -m "البداية: دمج نسخة سطح المكتب ونسخة أندرويد + بناء تلقائي موحّد"
   git branch -M main
   git remote add origin https://github.com/<اسم-حسابك>/<اسم-المستودع>.git
   git push -u origin main
   ```
3. افتح تبويب **Actions** بصفحة المستودع — راح تشوف "Build Desktop + Android" يعمل (يأخذ عدة دقائق لأنه يبني نسختين). بعد ما يخلص، افتح تبويب **Releases** وتلقى الملفين.
4. كل مرة بعدها تضيف ميزة (بأي المجلدين أو كليهما) وتسوي:
   ```bash
   git add .
   git commit -m "وصف التعديل"
   git push
   ```
   ينبني الملفين من جديد تلقائياً وتظهر نسخة Release جديدة.

## ملاحظة مهمة
لم يُبنَ أو يُختبر هذا المستودع فعلياً بهذه البيئة (لا توجد بيئة ويندوز لبناء exe، ولا Android SDK/محاكي هنا) — أول بناء حقيقي لكليهما سيحصل تلقائياً عبر GitHub Actions فور أول رفع (push). إذا ظهر أي خطأ بأي من الجزءين بتبويب Actions، ابعت رسالة الخطأ وأصلحها فوراً.

لتفاصيل كل نسخة على حدة (المتطلبات، هيكل الملفات، مكان تخزين البيانات...) راجع `desktop/README.md` و`android/README.md`.
